## 新的实物证据：当前配置与旧快照相同

在此前 [模式读取](Windows-USB-Mode-Queries.md) 确认当前数字为 30 后，仅通过父 USB hub 读取标准设备描述符和配置索引 0 描述符。没有打开控制串口、发送 AT 指令、读取字符串/序列号、发起厂商请求或业务数据传输。

证据：[本轮脱敏快照](IG831T-USB-Descriptors-Mode30-Recheck.json)，与 [2026-10-08 原快照](IG831T-USB-Descriptors.json) 比较。去掉采集时间后，两份解析 JSON 全部字段相同。采集时间保留工具原始 UTC 值，不改写成推测的执行时刻。本轮没有重新查询模式；模式 30 的关联依据是先前实测与期间未执行模式设置，不是从描述符反推数字。

| 项目 | 当前描述符结果 |
| --- | --- |
| USB 身份 | `2CA3:4009`，设备版本 `0x0318`，USB `0x0200` |
| 配置 | 一个配置，值 1，长度 209 字节，五个接口 |
| 接口 0 | `FF/FF/FF`，替代设置 0，两个 Bulk 端点 |
| 接口 1、2、3 | 各为 `FF/00/00`，替代设置 0，两个 Bulk 与一个 Interrupt 端点 |
| 接口 4 | `FF/FF/FF`，替代设置 0，两个 Bulk 与一个 Interrupt 端点 |

**观察：** 当前配置五个接口都是厂商类，没有标准 USB 网络类或音频类接口。**不能据此推断：** 所有其他固件/模式均不存在标准网络、厂商 Bulk 端点必然采用某种协议，或模块完全没有语音能力。额外 `0x24` 描述符头、端点布局和 Windows 兼容驱动也不能单独证明标准 NCM/ECM/MBIM 或可用双向音频。

这里比较的是两次解析描述符，不是全部 USB 原始字节、当前驱动绑定、长期网络稳定性或新的 Apple 真机验收。本轮没有重新发送 Internet 流量；Windows 联网成功仍依据此前 [固定模块路径 DNS/HTTPS 实测](Windows-PC-Internet.md)。原始描述符二进制和 hub 拓扑只留本机，公开快照不含设备实例后缀、GUID、SIM 标识或 IP 地址。
