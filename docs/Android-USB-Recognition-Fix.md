# Android 0.1.1：USB 识别流程与状态显示修复

日期：2026-11-17（香港）。用户实测 0.1.0 后报告读不到模块、没有 USB 授权框，只看到“未连接；不会自动访问 USB”。用户随后允许自行使用本机安卓/Linux 环境测试，并说明模块接在电脑上。未放宽“不影响 Windows 网卡、不改模块固件/模式”的限制。

## 已确认的程序缺陷

0.1.0 的 `message()` 把设备筛选/连接前错误写入 `events` 控件，但每秒 `render()` 又用服务的默认事件覆盖同一控件。结果可能是“系统没看到设备”“目标 PID 不匹配”等真实提示很快消失，界面仍停留在默认“未连接”，让用户无法判断故障层级。

此外，旧版在授权前只筛选 `2CA3:4009`，没有展示完整 USB 列表；USB 连接又要求接口条目总数必须等于 Windows 快照的 5。这些限制使“系统完全没枚举设备”“看到了未匹配身份”“接口条目数不同”被混在一起。但**目前仍没有取得用户 GSI 上的实际设备列表，不能断言总数过滤就是其唯一故障原因**。

## 0.1.1 的具体修改

- 独立、持续保存的阶段与错误历史，不再被一秒刷新盖掉；默认文案明确是等待用户操作，不冒充探测结论。
- 启动和点击“只读刷新 USB 设备列表”时，读取系统是否声明 USB Host、系统服务、实际设备数量、所有 VID/PID、接口/端点及已有授权状态。只读元数据，不申请权限、不打开设备、不发送 AT，不访问设备字符串/序列号。
- 把系统列表为空、列表不可读、目标未列出、多个目标、等待授权、已授权、打开/claim 控制口、AT 握手、模式查询和 SIM 查询分开显示。授权拒绝与服务启动失败也会保留。
- 已有授权时明确说明不会再次弹框，直接进入用户确认的连接步骤。没有授权则记录系统请求阶段，而不是静默显示默认“未连接”。
- 增加仅匹配 `2CA3:4009` 的 USB 插入声明，系统可提示打开应用；即便用户接受，App 也不会自动发送 AT，仍需手动连接。插入声明并不是驱动，不会让本来未被系统枚举的设备凭空出现。
- 不再仅凭“接口条目总数不是 5”拒绝设备。仍严格限制相同 VID/PID、唯一接口 2 / alt 0、`FF/00/00`、Bulk `84 IN / 03 OUT`，不试其他设备或接口、不强制抢占、不切配置；AT 之后仍只读确认模式 30。
- 诊断分享在 USB 未连接、尚未授权或服务失败时也可用，含真实系统列表及步骤历史，不含设备路径、序列号、SIM、短信正文、电话号码或 IP。
- 版本号升级到 `0.1.1` / versionCode `2`；构建清单改为读取实际 APK 的 `aapt` 元数据，不再硬编码 `0.1.0`。

## 本机实际完成的验证

1. 找到现有 Windows Android SDK（platform 35/36、build-tools 36）及 JDK 21。直接用本机 `aapt2`、`javac --release 8`、D8、zipalign、apksigner 构建了本地 0.1.1 APK；API 21 签名校验及包内能力核验通过。这是实际本地编译，不只是 CI 或静态检查。
2. 对生产 `UsbInventory`、`UsbBulkTransport` 和 `ConnectionStatus` 运行隔离的 Java / Android API 假对象回归：无服务、空列表、未声明 Host、权限元数据失败、未知 VID/PID、多个目标、7 个接口条目但已知控制口正确、错误端点拒绝、仅非强制 claim MI_02、不发送 Bulk 以及阶段历史保留/有界。全部通过。**假对象不是安卓系统或 USB 真机，不代表模块已能读取。**
3. 已定位的 SDK 路径没有 emulator/system-images，AVD 列表为空，ADB 没有已连接的安卓目标。Ubuntu 22.04 环境可以启动，但没有现成的 Java/ADB/Android SDK；没有擅自安装驱动、修改 ROM 或把模块透传给 VMware/WSL。
4. 只读核对了电脑当前模块：`MI_02 qcusbser`、`MI_04 qcusbwwan` 和父设备均 Code 0，模块网卡 `Up`；其他三接口仍 Code 28。见 [脱敏检查](Windows-USB-Preservation-Android-v0.1.1.json)。没有发送 PC AT 指令、联网流量、固件/模式命令或重新安装驱动。这不是新通话/联网测试，也不等于连续状态监测。

本地编译的 APK 使用本地临时测试签名；公开下载包以对应 GitHub 构建与 Release 为准，不能把本地 APK 的哈希/签名与 CI APK 混用。真实安卓 5/11 运行、用户平板 OTG、USB 授权与模块原始 Bulk AT 通信仍待实际验证。

## 用户醒来后只需看两个地方

新版先看顶部“系统 USB 设备数量”和 VID/PID，然后看“阶段”：

- **设备数 0：** 系统没有把 USB 设备列给 App；尚未走到权限/串口，需核对平板主机角色、数据线、供电和 GSI/厂商支持。不能靠增加短信权限、强发 AT 或切模块模式来假装修复。
- **有设备但不是 2CA3:4009：** 保留实际 VID/PID，分享报告；不自动猜测新身份。
- **目标出现但授权未完成：** 区分已有授权、拒绝、请求失败或等待系统对话框。
- **failed_at_usb_claim / failed_at_at_handshake：** 已看到设备，但接口被占用或 AT 未应答，和“没枚举 USB”不同；不强制卸载驱动或猜厂商初始化。

如安装提示签名不一致，需先释放旧 App 会话、确认没有未结束的呼叫，再卸载旧版并安装新测试包。短信/号码没有持久化到本 App，但卸载会清除应用自身数据。不要用卸载来代替结束真实电话。

这次修复的是已确认的状态显示、发现信息缺失与过度计数限制，**不能宣称已经修好用户 GSI 的硬件/驱动问题**。通话音频、系统模块数据驱动与无人机装回验证依然未完成。

资料：[Android 官方 USB Host 流程](https://developer.android.com/develop/connectivity/usb/host) 区分系统枚举、设备授权和接口通信。能编译或声明 Host feature，并不保证所有设备/ROM 提供 USB Host 能力。
