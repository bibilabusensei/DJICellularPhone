## Android 0.1.1：USB 发现与连接状态修复

针对 0.1.0 用户反馈“看不到模块、没有授权框、一直显示未连接”，修复已确认的软件问题：**连接前的错误会被每秒状态刷新盖掉**。现在不再只给一句“未连接”，而是直接显示系统 USB 列表和失败阶段。

### 下载与安装

在下方 **Assets** 下载 `DJICellularAndroid-debug.apk`，无需登录、解压或另签名。

这是新构建的测试签名 APK。如提示签名不一致，请先释放旧 App 的 USB 会话、确认无未结束呼叫，卸载 0.1.0 再安装 0.1.1。卸载会清除 App 自身数据；本 App 没有实现删除模块短信。不要用卸载代替挂断已开始的电话。

### 这次改了什么

- 错误和连接进度会保留，不再被“无业务操作”或默认等待文案覆盖。
- 顶部显示 Android/API/型号、USB Host 声明、系统 USB 设备数量、所有 VID/PID、接口与端点、是否已有授权；扫描只读，不打开设备或发送 AT。
- 即便不是已适配的 `2CA3:4009`，也会列出其身份帮助定位，不擅自访问其他设备。
- 区分列表为空、目标没列出、权限拒绝/已有授权、服务启动失败、打开/claim 控制口、AT 超时等阶段。已有授权时不重复等系统弹窗。
- 增加目标模块插入时的系统发现声明；不自动连接或发 AT。
- 去除“接口总数必须等于 5”的过度限制，但仍严格核验原目标、唯一 MI_02、类别和 Bulk `84/03`，不碰网卡接口、不强制抢占。
- 即便连接失败也能分享包含真实列表和步骤历史的诊断，不含设备路径、序列号、SIM、短信内容、电话号码或 IP。

### 醒来后怎么看结果

打开 **第一步：系统是否看到 USB**，点“只读刷新 USB 设备列表”：

1. **设备数量为 0：** 系统还没把任何 USB 设备列给 App；尚未进入授权/AT，需检查平板的 OTG 主机角色、数据线、供电或 GSI/厂商支持。
2. **有设备但没有 2CA3:4009：** 分享实际 VID/PID 列表，不要自行切模式或猜驱动。
3. **有目标：** 点第二步连接，查看保留下来的授权、接口和 AT 阶段；没有弹授权框也可能是已经授权，App 会明确写出。

**这不是已经验证修好 GSI 硬件/USB 驱动的承诺。** 当前没有用户平板的实际设备列表，也没有把插在电脑上的模块强制透传给虚拟机，以免丢失 Windows 网卡。

### 测试与限制

- 本机现有 Android SDK 完成了实际资源/Java/DEX 编译、APK 签名和 API 21 核验；另通过了隔离 Java/Android API 假对象的识别分支、控制口保护和错误保留回归。
- GitHub 也完成编译、lint、API/签名/能力核验。上述检查不是 Android 虚拟机或 GSI 真机运行，更不是模块实际短信、通话或数据测试。
- 最低系统仍为 Android 5（API 21），版本 `0.1.1` / versionCode `2`。
- **双向通话声音、用户态模块数据驱动、Android 系统蜂窝集成仍未实现。** 不要先开启收费呼叫实验，不用于正式或紧急通话。
- 不改固件、IMEI、APN、USB 模式、DTR/RTS、系统驱动、路由或电脑网卡；不安装 USB 透传/过滤驱动。设备上电和后台行为不是 App 能保证控制的。
