# 不改变工作配置的 Windows 联网复测

执行日期：2026-10-09（香港）。工具记录的 UTC 时间换算为香港时间：19:11:10 开始，19:13:20 完成。本次用户允许尝试满足以下限制的测试：不改固件，不让电脑失去模块网卡，不影响日后无人机使用，不影响电脑本机网卡。

据此仅执行已验证的状态读取与少量固定模块路径 DNS/HTTPS；模式 31 可能改变/移除工作接口，**不满足本次条件，未尝试**。前后比较不能保证硬件永不故障，也不能替代无人机实机验证，因此没有承诺绝对零风险或将来的无人机兼容性。

## 实际完成的检查

1. 在任何串口或业务请求前，保存目标设备绑定及电脑网络元数据。确认唯一 `2CA3:4009:MI_02` / `qcusbser` 和 `MI_04` / `qcusbwwan`，均 Code 0，并核对目标 COM 身份；不探测其他串口，不装驱动。
2. 固定发送三条已验证命令，各一次：`AT`、`AT+GTUSBMODE?`、`AT+CEREG?`。全部 `OK`，当前模式为 30，EPS 本地注册成立。DTR/RTS 禁用，读取有界；错误、超时、模式不是 30 或注册非本地即停止，没有选网/复位/拨号补救。
3. 关闭串口后、发送联网流量前，重新读取同一组元数据，与开始时完全相同，才进入流量阶段。此前旧注册记录没有被重标时间或复用为新状态。
4. 复用已有 `Test-IG831TInternet.ps1` 与 `IG831TInterfaceProbe.cs`：限制具体模块 IPv4 源地址及 `IP_UNICAST_IF`，只用该网卡配置的 DNS，核对目标接口选路，直接 TCP/TLS `HEAD`，校验主机名/证书，不回退电脑其他网卡、不用系统默认解析器或应用代理。
5. 请求完成后再次保存元数据。独立比较原始私有 JSON，确认前/中状态、前/后网络元数据以及目标设备绑定均相同；不只依赖脚本输出的成功标记。

证据：[本轮脱敏 JSON](Windows-Guarded-Connectivity-Recheck.json)。原始实例 ID、网卡 GUID、地址、DNS、路由及详细异常仅保留本机私有目录；没有抓取用户网络包或上传原始电脑配置。

## 这次结果能证明什么

本次再次验证了现有 Windows 工作配置上的模块联网，且所观察的电脑网络与模块绑定保持不变。它**不能证明** iPhone/iPad 可以直接识别当前厂商接口，也不能证明 SIM 普通电话、双向音频或所有将来的无人机功能。没有主动改写相关配置，是符合本次限制的做法；不是“已检验无人机以后一定正常”的结论。

后续仍保持模式 30。未知模式切换、固件修改、可能丢失网卡的驱动实验，以及依靠重新刷写来恢复的方案都不在当前许可内。下一步只研究适用协议/原厂资料及不会改变工作配置的验证；需要的定制模式与恢复说明见 [只读研究报告](USB-Mode30-ReadOnly-Research.md)，Apple 真实通信验收边界见 [可行性报告](Direct-USB-Voice-Feasibility.md)。
